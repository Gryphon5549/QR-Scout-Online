Use this website

Start guide

Want to send QR Scout match data into your own Google Sheet but you can't (or don't want to) host the website on GitHub Pages? Good news - you don't have to. You keep using this website as-is. You only need to (1) create a Google Cloud service account that is allowed to write into your sheet, (2) deploy the small backend on Render, and (3) paste your backend URL into this app. After that, every entry you commit lands in your own spreadsheet.

Part 1 - Create the Google service account

1

Open Google Cloud Console

Go to console.cloud.google.com and create a new project, or select an existing one.

2

Enable the Google Sheets API

Open APIs & Services → Library, search for Google Sheets API, and click Enable.

3

Create the service account

Open APIs & Services → Credentials → Create Credentials → Service account. Give it a name and finish creating it. This is your service email, which looks like your-name@your-project.iam.gserviceaccount.com.

4

Create a JSON key

Click the new service account, open the Keys tab, then Add Key → Create new key → JSON → Create. A .json file downloads. Keep it safe - it contains your private key.

5

Note the two values you need

Open the JSON file and copy these two fields:

  • client_email - the service email.
  • private_key - the long key starting with -----BEGIN PRIVATE KEY-----.
6

Create your own sheet and share it

Make a brand-new Google Sheet to hold your scouting data and copy its ID from the URL (the part between /d/ and /edit). Then click Share, paste the client_email, give it Editor access, and send. This is what lets the website write into your own sheet - without it the backend cannot add rows.

Part 2 - Deploy the backend to Render

7

Fork this repo (backend only)

Fork this repository into your own GitHub account so Render can build it. You only deploy the backend/ folder - the website itself stays hosted here, so you never set up GitHub Pages.

8

Create a Web Service on Render

Sign in to your render.com account, choose New → Web Service, and connect your forked repo. Set the Root Directory to backend, the Build Command to npm install, and the Start Command to npm start.

9

Add the environment variables

In the Render Environment tab, add these variables using the values from your JSON key:

GOOGLE_SHEET_ID=your_sheet_id_here
GOOGLE_SERVICE_ACCOUNT_EMAIL=your-name@your-project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...your key...\n-----END PRIVATE KEY-----\n"
SHEET_NAME=Scouting

Private key formatting

Paste the private_key exactly as it appears in the JSON file, keeping the \n sequences on a single line and wrapping the whole value in double quotes as shown. The server converts the \n into real line breaks for you.

10

Deploy and copy the URL

Click Create Web Service and wait for the deploy. Open https://your-app.onrender.com/health - you should see {"ok":true,...}. Your sync endpoint is:

https://your-app.onrender.com/api/sync-sheet

Part 3 - Use this website to send your data

11

Open this website

You're already on it - just make sure this site is open over https:// (or http://), not as a local file:// path. No GitHub Pages or local hosting needed.

12

Load a config

On the welcome screen, click Import config to upload your own JSON, or Load sample to start from the example config.

13

Save the sync URL

Click Show sync, paste your Render endpoint into Backend URL, optionally set a Tab name, then click Save sync.

14

Commit and sync

Fill out the form, click Commit, then choose Sync to Sheet. A new row appears in your own Google Sheet. You can also generate a QR code for an offline backup.

Troubleshooting

  • Missing ... in environment variables - a Render variable is empty or misspelled.
  • Permission or 403 errors - your sheet was not shared with the client_email as an Editor.
  • CORS or network errors - serve the site over HTTP/HTTPS and make sure the Backend URL ends in /api/sync-sheet.
