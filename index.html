Team 2549 • New setup

This is the new flow.

Use GitHub Pages for the website, Google Apps Script for the backend, and one shared Google Sheet as the live data destination.

1

Host the website

Put the frontend on GitHub Pages. This keeps the app simple and fast and lets the browser load it over a real website URL.

2

Deploy the script

Create a Google Apps Script and deploy it as a Web App. This is the only backend the browser can use to append rows to a sheet.

3

Use the sheet link

Paste the shared Google Sheet link into the app. The script reads the sheet ID from that URL and appends the row into the tab you choose.

4

Submit a scouting entry

Fill in the form, click Commit, and choose Sync to Sheet. The website sends a POST to the Apps Script URL, and the script writes the row to the sheet.

5

Keep it simple

No Google Form mapping. No confusing legacy fields. Just one site URL, one script URL, and one sheet link.

Exact setup steps

  1. Push the website to GitHub and enable GitHub Pages.
  2. In Google Apps Script, create a project and paste in the backend script.
  3. Deploy it as a Web App with “Execute as: Me” and “Who has access: Anyone”.
  4. Copy the deployed Web App URL and paste it into the site.
  5. Copy the shared Google Sheet link and paste it into the site.
  6. Optional: enter a tab name such as “Scouting” or leave it blank to use Sheet1.
  7. Save and test the sync once to confirm it writes a real row.

Rules to remember

  • Always open the site over a real URL, not a file path.
  • Use the Apps Script Web App URL ending in /exec, not the sheet URL.
  • Use a shared Google Sheet link so the script can open the spreadsheet.
  • Keep the script deployed as Anyone so the browser can call it from GitHub Pages.
  • If the browser still fails, refresh the live page and test again with the deployed URL.
